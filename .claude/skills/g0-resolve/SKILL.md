# G0 항목 정정안 작성

**한 번에 한 항목만.** 여러 항목을 묶으면 사람이 승인 단위를 나눌 수 없다.

## 0. 전제

G0 는 **명세 결함**이지 구현 과제가 아니다. 결과물은 코드가 아니라
"명세를 이렇게 고치자"는 **문안 초안**이다. 승인권은 사람에게 있다.

`docs/` 와 `Cogito++_*.md` 는 Claude 소유지만, **승인 전에는 명세 본문을 고치지 않는다.**
초안을 제시하고 승인을 받은 뒤 반영한다.

## 1. 항목 원문 확보

`Cogito++_개발_작업체크리스트.md` §2-2 표에서 해당 행을 그대로 인용한다.

| 읽을 것 | 왜 |
| --- | --- |
| 발견 내용 | 무엇이 문제인지 |
| 권장 확정 방향 | 체크리스트 작성자의 의견 (구속력 없음) |
| 종료 증거 | 이 항목이 닫혔다고 인정받는 조건 |

## 2. 근거 수집 — 기억으로 하지 않는다

명세에서 **충돌하는 두 지점을 모두 원문으로** 찾아온다.

```
Grep 으로 관련 절을 전수 수집 → 각각 원문 인용 → 어디서 갈라지는지 명시
```

- 사실 확인이 필요하면 `fact-checker` 서브에이전트를 쓴다.
- 명세 전반의 자기모순이 의심되면 `/spec-consistency` 를 먼저 돌린다.
- 산출물과의 대조가 필요하면 `spec-auditor` 서브에이전트를 쓴다.

## 3. 선택지를 2~3개로 좁힌다

각 선택지마다:

- **무엇을 확정하는가** (구체적 값·문장)
- **무엇을 포기하는가** (트레이드오프)
- **되돌릴 수 있는가** — 나중에 바꾸면 기존 감사 데이터·골든 벡터·승인 기록이 무효가 되는가
- **누가 결정해야 하는가** — Claude 가 정할 수 있는가, 사람만 정할 수 있는가

되돌릴 수 없는 결정(digest·canonical 형식·감사 스키마)은 **반드시 그렇다고 표기**한다.

## 4. 권고안 하나를 고른다

"둘 다 가능합니다"로 끝내지 않는다. **하나를 고르고 이유를 댄다.**
다만 §16 외부 결정(인증원·설비값·공급망·CI 주체)에 해당하면
"제품 책임자 결정 필요"로 명시하고 선택지만 정리한다.

## 5. 산출물 형식

```markdown
## G0-NN 정정안

**차단 수준**: (체크리스트 원문)
**되돌림 가능성**: 가능 / 불가 (불가면 이유)

### 현재 상태 — 무엇이 어긋나 있는가
- 명세 §A: "원문 인용"
- 명세 §B: "원문 인용"
- 충돌 지점: …

### 선택지
| # | 확정 내용 | 포기하는 것 | 되돌림 |
|---|---|---|---|

### 권고: (선택지 번호)
이유:

### 확정 문안 (명세에 그대로 들어갈 문장)
> …

### 영향 범위 — 함께 고쳐야 할 곳
- Cogito++_구현명세서.md §…
- 체크리스트 §…
- 관련 ADR: …
- 영향받는 테스트/골든 벡터: …
- 다른 AI 에게 인계할 것: (있으면 /handoff 형식으로)

### 종료 증거 (체크리스트가 요구한 것)
- [ ] …
```

## 6. 다음 단계 연결

- 이 결정이 ADR 로 남아야 하면 `/adr-draft` 로 이어간다.
- 다른 에이전트의 산출물을 고쳐야 하면 `/handoff` 로 이슈를 만든다.
- 승인 후 명세 반영까지 마쳤으면 체크리스트 §2-3 의 해당 체크를 갱신한다.

## 금지

- 명세에 없는 값을 임의로 채우고 "확정"이라 부르지 않는다. 근거가 없으면 "제품 책임자 결정 필요"다.
- 부록 A 의 금지 문구를 쓰지 않는다.
- 여러 G0 항목을 한 문서에 섞지 않는다.
