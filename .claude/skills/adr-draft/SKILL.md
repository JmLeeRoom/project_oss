```markdown
## 맥락

## 결정
확정 문안. 구현자가 추가 판단 없이 따를 수 있을 만큼 구체적으로.

## 롤백·마이그레이션 영향
- 이미 생성된 감사 데이터가 무효화되는가
- 골든 벡터/픽스처를 다시 만들어야 하는가
- 기존 승인 기록이 검증 불가가 되는가
- 다른 AI 의 산출물에 파급되는가 (누구에게 /handoff 필요한가)

## 검증 방법
이 결정이 지켜졌는지 확인하는 테스트 이름 또는 명령.
"코드 리뷰로 확인"은 검증 방법이 아니다.

## 미결
이 ADR 로 닫히지 않는 것. 누가 결정해야 하는가.
```

## 절차

1. **관련 G0 항목과 명세 절을 먼저 읽는다.** 기억으로 쓰지 않는다.
2. 사실 확인이 필요하면 `fact-checker` 를 쓴다.
3. 명세 내부 모순이 근거라면 `/spec-consistency` 결과를 인용한다.
4. **대안을 최소 2개** 실제로 비교한다. 하나만 쓰면 결정이 아니라 통보다.
5. `docs/adr/NNNN-slug.md` 로 저장한다.
6. 사용자에게 **결정이 필요한 지점만** 요약해 전달한다.

## 금지

- 승인 없이 `Accepted` 로 표기하지 않는다.
- 승인 없이 명세 본문에 반영하지 않는다.
- §16 외부 결정(인증원·설비값·CI 주체·법무)을 Claude 가 확정하지 않는다.
  선택지와 트레이드오프만 정리하고 "제품 책임자 결정 필요"로 남긴다.
- 부록 A 금지 문구를 쓰지 않는다.
