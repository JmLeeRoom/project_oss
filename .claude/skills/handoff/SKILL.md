# 다른 에이전트에게 인계

## 원칙

**남의 파일을 고치지 않는다.** 3-AI 가 한 저장소를 쓰므로 경계를 넘으면
같은 파일을 두 에이전트가 서로 다른 계약으로 고치게 된다.

가드에 막혔다면 그건 버그가 아니라 **설계대로 동작한 것**이다.
`scripts/ownership-policy.json` 을 우회하려 하지 말고 이 스킬을 쓴다.

## 대상 판정

`scripts/ownership-policy.json` 의 rules 로 소유자를 확인한다.

| 소유자 | 영역 | 피드백 신호 |
| --- | --- | --- |
| **codex** | `src/**` `tests/**` `cmake/**` `CMakeLists.txt` `vcpkg*.json` `tools/cli/**` `tools/web_host/**` `bindings/**` | 컴파일러 · ctest |
| **antigravity** | `tools/web_dashboard/**` `tools/mock_server/**` `tests/web/**` `.agents/**` | 브라우저 · CSP · 스크린샷 |
| **사람** | §16 외부 결정, ADR 승인, 법무, 실설비 | — |

## 작성 형식 (체크리스트 §1-2 그대로)

```text
Task ID:            HO-<대상>-<연번>
원본 근거:          Cogito++_구현명세서.md §...
선행 작업:
변경 파일:
구현 범위:
비범위:
실패 모드:
검증 명령:
테스트 결과:
안전 영향(write 0회 근거 포함):
산출물/로그 위치:
검토자:
```

여기에 인계 전용 항목을 덧붙인다.

```text
발견 경위:          (어떤 리뷰/작업 중 발견했는가)
불변식 영향:        (CLAUDE.md §5 의 몇 번인가, 없으면 "없음")
재현 방법:          (구체적 순서. 없으면 "정적 검토")
권위 근거:          (명세 원문 인용 — 내 의견이 아니라 계약이라는 증거)
제안 수정:          (강제가 아니라 제안임을 명시)
차단 여부:          blocking / non-blocking
```

## 절차

1. **소유자를 확정한다.** 애매하면 인계하지 말고 사람에게 판정을 요청한다.
2. **권위 근거를 원문으로 인용한다.** "제 생각에는" 은 인계 사유가 아니다.
   명세 §번호와 원문이 있어야 상대가 논쟁 없이 수용한다.
3. **재현 방법을 쓴다.** 정적 검토라면 그렇게 쓴다. 확실하지 않으면 "확인 필요"로 표기한다.
4. **불변식 영향을 판정한다.** 안전 불변식에 걸리면 `blocking` 이다.
5. `docs/handoff/HO-<대상>-<연번>.md` 로 저장한다.
6. 사용자에게 **한 문단으로 요약**해 전달한다 — 어디로, 무엇을, 왜 blocking 인지.

## 역방향 인계 (다른 AI → Claude)

Codex/Antigravity 가 헤더 계약·명세·config 스키마 문제를 올려보내면:

1. `spec-auditor` 로 실제 계약 위반인지 대조한다.
2. 명세 수정이 필요하면 `/g0-resolve` 또는 `/adr-draft` 로 이어간다.
3. **명세를 바로 고치지 않는다.** 승인 후 반영한다.

## 금지

- 가드를 우회하려고 `ownership-policy.json` 을 임의 수정하지 않는다.
- 남의 영역 코드를 "참고용으로" 작성해 붙이지 않는다. 제안은 산문으로 한다.
  (상대가 그대로 붙여넣으면 리뷰 없이 계약이 바뀐다)
- 근거 없는 스타일 지적을 인계하지 않는다. 계약 위반과 취향을 구분한다.
